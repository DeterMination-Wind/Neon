# 全局写作与格式约定

本文件是 Neon 仓库的**全局写作宪法**：凡是面向人类阅读的文本，均按本文件规则编写。它约束文档、Issue 模板、提交信息、Release 说明与代理产出，优先级高于各处零散习惯；与 `AGENTS.md` 冲突时，行为约束以 `AGENTS.md` 为准，排版格式以本文件为准。

## 禁止软换行

**一段一行，不要在句子中间手动敲回车。**

Markdown、Issue Forms、提交信息、PR 描述和 Release Notes 都会由渲染器或阅读界面自动折行。手动按屏幕宽度折断句子只会制造噪音：渲染后的行内空隙不可控，diff 里一句改动会散落到多行，移动端与桌面端宽度不同也会导致折行位置全面错位。把折行交给渲染器，作者只负责分段。

适用范围：

- `docs/` 下所有 `.md` 文件，以及根目录的 `README.md`、`FEATURES.md`、`RELEASE_NOTES.md`。
- `.github/ISSUE_TEMPLATE/` 中的 `description`、`about`、`label`、`placeholder`、`value` 等文案字段。
- Git 提交信息的标题与正文段落。
- PR 描述、Issue 正文与代码评审意见。
- 代理在对话中输出的说明文字。

例外（以下换行具有结构意义，必须保留）：

- 列表项：每个条目独立成行。
- 表格：每行一条记录。
- 代码块、YAML 块标量、JSON 等结构化内容。
- 复现步骤、命令序列、按键序列等逐步操作。
- 单个段落本身就是一个短句时，自然只有一行。

不受本规则约束的部分：

- 源码（`.java`、`.kt`、`.gradle` 等）：由格式化器与行宽规则管理，不按散文排版。

## 提交信息

- 标题占一行，格式为 `Neon: <概要>`，不超过一屏可读长度，末尾不加句号。
- 正文按段落书写，**每段一行**，段落之间空一行；不要为对齐或控制宽度而折断句子。
- 需要列点说明时使用 `-` 列表，每条一行。
- 不要在标题中塞入多句解释，细节写入正文。

判断标准很简单：将渲染宽度减半或加倍后，文本仍只在段落边界处断开，即符合要求。

## 自检

提交前检查改动：

```powershell
git diff --cached          # 文档与模板：检查正文段落是否被拆成多行
git log -1 --pretty=%B     # 提交信息：检查段落是否被手动折断
```

若发现一段话跨越多行，且各行并非独立句子、列表项或表格行，应合并回同一行。

Issue 模板等 YAML 文案字段不单独做自动检查：`value: |` 中的段落、`label` 与 `description` 均应写成一行，仅为了控制宽度而添加的续行即视为违规。
