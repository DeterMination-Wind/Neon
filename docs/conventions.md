# 全局写作与格式约定

本文件是 Neon 仓库的**全局宪法**：凡是写给人看的文本，都按这里的规则写。它约束文档、Issue 模板、提交信息、Release 说明与代理产出，优先级高于各处的零散习惯；与 `AGENTS.md` 冲突时，行为约束看 `AGENTS.md`，排版格式看本文件。

## 禁止软换行

**一段一行。不要在句子中间手动敲回车。**

Markdown、Issue Forms、提交信息、PR 描述、Release Notes 都属于会由渲染器或阅读界面重新折行的文本。手动按屏幕宽度折断句子只会制造噪音：渲染后行内空隙不可控、diff 里一句改动散成多行、手机端与桌面端宽度不同导致折行位置全部错位。把折行交给渲染器，作者只负责分段。

适用范围：

- `docs/` 下所有 `.md`、根目录 `README.md`、`FEATURES.md`、`RELEASE_NOTES.md`。
- `.github/ISSUE_TEMPLATE/` 中的 `description`、`about`、`label`、`placeholder`、`value` 等文案字段。
- Git 提交信息的标题与正文段落。
- PR 描述、Issue 正文、代码评审意见。
- 代理在对话中输出的说明文字。

例外（这些换行有结构意义，必须保留）：

- 列表项：每个条目独立成行。
- 表格：每行一条记录。
- 代码块、YAML 块标量、JSON 等结构化内容。
- 复现步骤、命令序列、按键序列等逐步操作。
- 单个段落本身就是一个短句时，它自然只有一行。

不受本规则约束的部分：

- 源码（`.java`、`.kt`、`.gradle` 等）。它们由格式化器与行宽规则管理，不按散文排版。

## 提交信息

- 标题一行，格式 `Neon: <概要>`，不超过一屏可读长度，不加句号。
- 正文分段落，**每段一行**，段落之间空行；不要为了对齐或控制宽度折断句子。
- 需要列点说明时用 `-` 列表，每条一行。
- 不要在标题里塞多句解释；细节放正文。

判断标准很简单：把渲染宽度换成一半或两倍，文本仍然只在段落边界断开，就是对的。

## 自检

提交前扫一眼改动：

```powershell
git diff --cached          # 文档与模板：正文段落是否被拆成多行
git log -1 --pretty=%B     # 提交信息：段落是否被手动折断
```

发现一段话跨了多行、且每行都不是独立句子、列表项或表格行，就合并回一行。

Issue 模板等 YAML 文案字段不单独做自动检查：`value: |` 里的段落、`label` 与 `description` 都应是一行，出现只为了控制宽度的续行即视为违规。
