# 子系统：模组更新中心（modUpdater）

更新中心把 Neon 内所有子模组（以及用户安装的其他 mod）的更新检查收进一个界面。它是聚合化的直接受益者：并入前每个子模组各自弹"发现新版本"，现在只在这里检查一次。

## 状态模型

对每个被检查的仓库，列表必居其一：

| 状态 | 含义 | 操作 |
| --- | --- | --- |
| 可更新 | GitHub Release 有比本地新的版本 | 单个更新或勾选批量 |
| 已最新 | 与最新 Release 一致 | 无 |
| 黑名单 | 用户明确不想跟更的仓库 | 不再提示 |
| 无仓库 | 没有 `repo` 元数据或覆盖配置 | 不可更新 |

## 功能面

- **单个/批量更新**：下载新版本替换本地 mod 文件。
- **仓库覆盖（repository override）**：给没有正确 `repo` 描述的 jar 手工指定 `owner/repo`。
- **黑名单**：按仓库屏蔽检查，避免特定 mod 反复打扰或误升。
- **镜像切换**：GitHub 直连之外的下载通道；可用性取决于网络环境。

## 版本号兼容

更新器要读三种历史版本格式并比较大小：

1. 当前数字版本码：`N12 → 120000`、`B12.5 → 120005`；
2. 预发行数字码（`B*` 编码）；
3. 历史 `vX.Y.Z` 字符串（老 BEK-Tools 时代产物）。

换算逻辑集中在 `modupdater.features.VersionUtil`，回归测试为 `versionUtilTest`（接在 `gradlew test` 上）。**任何动版本解析的改动都必须让该任务保持全绿**，规则细节见[版本与发布](../release.md)。

## 聚合环境约束

- 子模组各自的"启动时查更新"逻辑在并入时必须移除，统一由更新中心负责——这也是[接入清单](../development.md)的第 10 条。
- 更新中心自身作为模块受核心故障隔离保护：初始化失败不影响其余功能。

## 排障

- **某 mod 一直显示无仓库**：先确认其 `mod.json`/`mod.hjson` 是否含 `repo` 字段；没有就手工加仓库覆盖。
- **下载失败但直连浏览器可以**：切镜像试试；仍失败多半是该 Release 的资产不符合"唯一 jar"规则，用 `gh release view <tag> --json assets` 查看该仓库资产列表。
- **版本比较结果可疑**：拿实际版本串复现到 `VersionUtilTest` 里补一条断言再修逻辑。
