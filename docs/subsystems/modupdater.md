# 子系统：模组更新中心（modUpdater）

模组更新中心将 Neon 内所有子模组（以及玩家安装的其他模组）的更新检查集中到同一个界面。它是聚合架构的直接受益者：并入前每个子模组会各自弹出“发现新版本”，如今只需在此统一检查一次。

## 状态模型

每个被检查的仓库必然处于以下四种状态之一：

| 状态 | 含义 | 可执行操作 |
| --- | --- | --- |
| 可更新 | GitHub Release 存在高于本地的版本 | 单个更新或勾选批量更新 |
| 已最新 | 与最新 Release 版本一致 | 无 |
| 黑名单 | 用户明确屏蔽跟进更新的仓库 | 不再提示 |
| 无仓库 | 缺少 `repo` 元数据且未配置仓库覆盖 | 不可更新 |

## 核心功能

- **单个 / 批量更新**：下载新版本并替换本地模组文件。
- **仓库覆盖（repository override）**：为缺少有效 `repo` 字段的 JAR 手动指定 `owner/repo`。
- **黑名单**：按仓库屏蔽更新检查，避免特定模组反复提醒或误升级。
- **镜像切换**：提供 GitHub 直连之外的备选下载通道，实际可用性取决于当前网络环境。

## 版本号兼容

更新器需要解析并比较三种历史版本格式：

1. 当前数字版本码：`N12 → 120000`、`B12.5 → 120005`。
2. 预发行数字版本码（`B*` 编码）。
3. 历史 `vX.Y.Z` 字符串（旧 BEK-Tools 时代遗留格式）。

换算与比较逻辑集中在 `modupdater.features.VersionUtil`，并由挂接在 `gradlew test` 上的回归任务 `versionUtilTest` 保护。**任何涉及版本解析的改动都必须保证 `versionUtilTest` 全绿**，版本码规则详见 [版本与发布](../release.md)。

## 聚合环境约束

- 子模组自带的“启动时检查更新”逻辑在并入 Neon 时必须移除，统一由更新中心接管（对应 [开发指南接入清单](../development.md) 第 9 条）。
- 更新中心本身同样受聚合核心的故障隔离保护，其初始化失败不会影响其他功能正常运行。

## 排障指南

- **某模组一直显示「无仓库」**：先检查其 `mod.json` / `mod.hjson` 是否包含 `repo` 字段；若缺失，手动为其添加仓库覆盖。
- **下载失败但浏览器可直连**：先尝试切换镜像；若仍失败，通常是该 Release 的资产不符合“唯一 JAR”规则，可用 `gh release view <tag> --json assets` 检查资产列表。
- **版本比较结果异常**：先将实际版本字符串补充到 `VersionUtilTest` 中复现并添加断言，再修复解析逻辑。
